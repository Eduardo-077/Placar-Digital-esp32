FASE 2 - ELEGANTOTA (atualizar o ESP pelo Wi-Fi)
================================================================
Por que: com o placar fechado na carcaça 3D, não precisa abrir para
ligar o USB.

1. Instalar a biblioteca "ElegantOTA" (ayushsharma82) no Library Manager.
2. Usar o WebServer.h que já vem no ESP32:
     #include <WebServer.h>
     #include <ElegantOTA.h>
     WebServer servidor(80);
   No setup, depois do Wi-Fi:
     ElegantOTA.begin(&servidor);
     ElegantOTA.setAuth(OTA_USUARIO, OTA_SENHA);   // no segredos.h
     servidor.begin();
   No loop:
     servidor.handleClient();
     ElegantOTA.loop();
3. Adicionar OTA_USUARIO e OTA_SENHA no segredos.h E no
   segredos_exemplo.h (com valores falsos).
4. Mostrar o IP num canto da tela inicial (fica fácil achar).
5. Gerar o .bin: Sketch -> Export Compiled Binary.
   Abrir http://IP_DO_ESP/update no navegador e enviar o .bin.
6. Teste: mudar um texto da tela inicial, atualizar pelo navegador,
   ver a mudança sem cabo.
Limite: só funciona na mesma rede do ESP (ver ZeroTier na Fase 3).


================================================================
FASE 3 - SERVIDOR UBUNTU + ZEROTIER
================================================================
Onde rodar o Ubuntu Server (escolher um):
  a) Máquina virtual (VirtualBox) no notebook de alguém. Mais fácil.
  b) PC velho / Raspberry Pi. Fica ligado direto.
  c) VM gratuita na nuvem (ex.: Oracle Cloud Always Free).

1. Instalar Ubuntu Server, depois Docker e o plugin docker compose.
2. Criar a pasta servidor/ no repositório com um docker-compose.yml
   que sobe 3 serviços:
     - influxdb:2   (porta 8086)
     - grafana      (porta 3000)
     - nodered      (porta 1880)
   Senhas e tokens num servidor/.env, que vai no .gitignore.
   Versionar só um servidor/.env.exemplo.
3. ZeroTier:
   - Criar uma rede em my.zerotier.com (grátis), anotar o Network ID.
   - Instalar no servidor e nos notebooks do grupo:
       curl -s https://install.zerotier.com | sudo bash
       sudo zerotier-cli join <NETWORK_ID>
   - Autorizar cada máquina no painel do ZeroTier.
   - Resultado: todo mundo abre o Grafana/Node-RED pelo IP do ZeroTier
     (ex.: http://10.147.x.x:3000), mesmo em casa ou na rede da UFSM.
   - Bônus: se o servidor estiver na mesma rede do placar, ele pode
     repassar a OTA (o grupo atualiza o ESP de longe).


================================================================
FASE 4 - EVENTOS DA PARTIDA (ESP -> SUPABASE)
================================================================
Hoje os dados só vão do celular para o ESP. Para ter gráficos, o ESP
precisa mandar o que acontece no jogo.

1. Nova tabela no Supabase, "eventos":
     id, partida_id, placar_id, tipo, time, placar_a, placar_b,
     tempo_jogo_s, created_at
   tipo: 'inicio', 'ponto', 'correcao', 'falta', 'pausa',
         'fim_periodo', 'fim'
   time: 'A', 'B' ou vazio
2. Segurança igual à das partidas: RLS ligado, leitura pública e
   gravação só por função registrar_evento(p_token, ...), que confere
   um token do placar (tabela segredos, como o PIN).
   O token vai no segredos.h.
3. Nova tabela "telemetria" (a cada 60 s):
     rssi (sinal do Wi-Fi), heap_livre, uptime_s,
     luz (sensor de luz da placa no IO34, analogRead)
   É o "dado de sensor" de verdade do projeto, e serve para saber se o
   placar está online.
4. No ESP: cada gol/ponto/falta vira um item na fila da tarefa de rede
   (Fase 0, item 2), que chama a função pelo /rest/v1/rpc/.
5. Bônus barato: o HTML mostra o placar AO VIVO lendo o último evento
   (era a "Etapa 5" do roteiro_supabase).

FASE 5 - NODE-RED (Supabase -> InfluxDB)
================================================================
Fluxo principal:
  [inject a cada 5 s] -> [http request: GET /rest/v1/eventos?id=gt.ULTIMO]
    -> [split] -> [function: monta o ponto do Influx] -> [influxdb out]
- Guardar o último id lido no contexto do fluxo (flow.set / flow.get).
- Mesmo fluxo para a tabela telemetria.
- Paleta extra: node-red-contrib-influxdb.
- Exportar o fluxo (Menu -> Export -> JSON) para servidor/nodered/flows.json
  no repositório.

Automações (escolher 1 ou 2 para mostrar):
- Placar offline: se não chegar telemetria em 3 min, avisar
  (e-mail/Telegram).
- Fim de jogo: mandar o resultado final numa mensagem.
